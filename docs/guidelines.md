# AI エージェント運用指針とリポジトリ公開ルール

本ドキュメントは、kairn の開発および本リポジトリを扱う AI エージェント（Claude Code / Codex / OpenCode / Antigravity 等）の運用指針と、リモートリポジトリ（GitHub 等）への公開・プッシュに関する規則を定めます。

作業者ごとの個別エージェント設定（`CLAUDE.md`, `AGENTS.md`, `ACTION_PRINCIPLES.md` 等）は各自の環境やワークスペースに合わせて管理されますが、本リポジトリ全体に関わる共通の指針として以下を遵守してください。

---

## 1. リポジトリ公開ルール（コミット・プッシュ前の必須要件）

### 1.1. 実データ・機密の完全分離
- **`workspaces/` の非コミット**: 各案件の実データ（`workspaces/<ws>/cases/`）や索引（`workspaces/<ws>/index/`）はローカルおよび Google Drive 上でのみ同期・保持され、Git の追跡対象外（`.gitignore`）です。決して強制コミット（`git add -f` 等）しないでください。
- **認証情報・トークンの排除**: Google Drive の OAuth クライアント情報、各種 API トークン、秘密鍵、`.env`、実体の `config.yaml` などをリポジトリ内にコミット・公開してはなりません。

### 1.2. 固有名詞（実顧客名・実プロジェクト名・実案件名）の排除
- **架空・抽象識別子の使用**: コードベース、テストコード、ドキュメントに実在の顧客名、社名、プロジェクト名、実際の案件名・チケット番号を含めてはなりません。
- **サンプルの命名規則**:
  - ワークスペース名: `acme`, `beta` などの抽象名
  - 案件 ID: `CASE-1`, `CASE-NEW`, `mock-nav-turn` などの一般的な識別子
  - リポジトリ名: `repo-a`, `proj-x` など

### 1.3. コミット・プッシュ・公開の明示的承認制
- `git commit`, `git push`, PR 作成、およびリモートリポジトリの新規作成・公開範囲変更（Public / Private）は、**作業者からの直前の明示的な実行指示**がある場合のみ実行します。
- 目標の説明や方針への同意（「〜を公開したい」「〜を push 予定」など）を実行指示と解釈して自律的に外部操作を実行してはなりません。

### 1.4. 公開前監査（Pre-push Audit）
リモートリポジトリへの初回プッシュまたは公開前には、以下の検証を必ず行います：
1. **秘密情報スキャン**: トークン・秘密鍵パターン（`ghp_`, `token`, `secret` 等）の検索
2. **実案件名・固有名詞スキャン**: 実環境の `workspaces/` に存在する実際のディレクトリ名や顧客名がコードやコミット履歴に混入していないかの検索
3. **未追跡・差分確認**: `git status --ignored` および `git diff` で意図しないファイルやデータが含まれていないことの確認

---

## 2. AI エージェント運用の基本指針

1. **結果の保証者は人間**:
   - AI は自身の出力や安全性を自律的に完全保証できません。人間が追試・監査できるよう、確認した事実（コマンド実行結果、差分）と推論過程を検証可能な形で提示してください。
2. **判断ロジックは MCP 側に委ねる**:
   - 案件の作成・ステータス変更・タスク完了の証拠検証などは MCP サーバー（`kairn`）が強制します。エージェントが自己判断でルールを迂回するスクリプトや直接のファイル改ざんを行わないでください。
3. **文脈の隔離**:
   - 案件の知見抽出（extract）などを行う際は、他のワークスペースやリポジトリのコンテキストが混ざらないよう、隔離された環境で実行してください。
