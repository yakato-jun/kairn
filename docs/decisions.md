# 設計判断

| # | 判断 | 理由 |
|---|---|---|
| 1 | ワークスペース（顧客・組織単位）を最上位の境界とし、保存先・索引・抽出をまたがない | 案件データを組織の境界で隔離する。同じ組織の複数リポジトリは 1 つの案件領域を共有し、案件はリポジトリに属さない |
| 2 | クラウドストレージ（rclone remote）を正本、ローカルは写し。remote は setup 時に利用者が指定し、それ以外を使わない | 複数環境で同じ案件を扱える。ローカルは容量逼迫時に消してよい。意図しないアカウントへ書き込まない |
| 3 | 環境ごとのリポジトリ紐付けはコマンド（`kairn attach`）で明示し、設定ファイルは kairn が書く。紐付け情報はリポジトリに含めない。案件の置き場は `workspaces/<ws>/cases/` のみで、リポジトリ側に `tmp/` 等のシンボリックリンクを張らない（2026-09-02 に廃止）。エージェントは `open_case` が返す `paths.case_dir` の絶対パスで読み書きし、その領域へのアクセスは各エージェントの「追加ディレクトリ許可」設定で開ける | clone 先は環境ごとに異なる。ローカルパスや組織名をリポジトリに残さない。案件はリポジトリに属さないので、リポジトリ側に痕跡を残さず、既存の `tmp/` 実体との衝突判定も不要にする |
| 4 | 人が操作するのは UI のみ。ファイルは AI と kairn が読み書きする | AI の作業状況を人が画面で把握し指示するための道具であり、記録ファイルの保守を人に求めない |
| 5 | タスクは「計画の版」に属し、新版に引き継がれなかった open タスクは自動的に superseded。閉じる操作を要求しない | 方針が変わって不要になったタスクが残り続けないよう、計画の出し直しを閉じる操作と一体にする |
| 6 | AI の done は証拠（commit / PR / file / test）必須。MCP が拒否する | 「AI が何をどこまでやったか」を検証可能にする。指示文ではなく実装で担保する |
| 7 | 判断ロジックは MCP 側に置き、各エージェントの skill は「いつ何を呼ぶか」だけを記す | 複数のエージェント（Claude Code / Codex / OpenCode）で同じ SKILL.md を共有し、エージェント差で運用が崩れないようにする |
| 8 | 案件カードの下書き抽出は文脈隔離した子プロセスのエージェントで行い、アダプタで切り替える。結果は下書きで、確定は人 | 作業中のセッションの文脈を抽出で汚さない。エージェントは利用者の環境で選べる。知見を自動確定しない |
| 9 | 索引は SQLite FTS5（trigram）。索引作成に LLM を使わない | 日本語の部分一致が必要。索引は写しから再生成できる派生物に留める |
| 10 | 大容量の生データは一定期間後にクラウドへ移動し、案件に所在を記録する。ビルド産物とシンボリックリンクは同期しない | 容量を空けつつ復元可能にし、同期対象を明確にする |
| 11 | 生データの判定は「（拡張子が対象 OR サイズが min_size 超）AND 更新から min_age 超」。rclone へは `--filter` 規則（`- <exclude>` → `+ *.{ext}` → `- **`）で渡し、拡張子パスとサイズパスの 2 回に分ける | `--include` と `--exclude` の併用は rclone が順序不定と警告し、実測で除外が効かない。1 回の呼び出しでは include と min-size が AND になる（2026-09-02 段階 2 で確定） |
| 12 | 生データの所在は `worklog.md` があればその `## Data location` 節、無ければ `DATA.md` に書く（case.json の有無に関わらず）。`daily --dry-run` は drive-index.txt と索引を書き換えない | 記録先を「AI が書く経緯の文書」に寄せつつ、案件化前のディレクトリでも所在を失わない。dry-run は観察のみで副作用を残さない |
| 13 | 案件ごとに `last_checkin_at` を持ち、`open_case` はそれより新しいローカル変更があれば checkout を skip する。`open_case` は取り寄せ → 読み込みの順 | 未 checkin の変更を Drive の版で上書きしない。Drive にしか無い案件も開ける。返り値とディスクの食い違いを無くす |
| 14 | `events.jsonl` は checkout / checkin の前に Drive 版と行の和集合にマージする（重複は文字列一致、`t` で安定ソート）。`open_case` は events に書かず、閲覧記録はローカルの `index/access.log` へ | 追記専用ログを「新しい方で上書き」すると複数環境の行が失われる。閲覧のたびに追記するとローカルが常に新しくなり他環境の event を取り込めない（2026-09-02） |
| 15 | 常駐は systemd user service。unit は kairn 自身（`kairn install-service`）がコード内テンプレートから生成し、実行中の自分のパスを ExecStart に埋める。雛形ファイルは置かない | clone 先・導入方法（uv tool / venv）ごとに変わるパスを人に書き換えさせない。`kairn ensure` は service が止まっていた時の保険で、常駐の代替ではない（2026-09-02） |
| 16 | MCP の `checkin` と `open_case` の取り寄せはプロセス内ジョブ（`kairn/jobs.py`、デーモンスレッド）にし、ツールは待たずに `job_id` を返す。状態は `job_status`。同一案件・同種のジョブは重複起動しない。ジョブ表はメモリ内でサーバー再起動で消える。CLI の `checkin` / `checkout` は同期のまま | 大きな案件（数百 MB・数百ファイル）の rclone は MCP クライアントの呼び出しタイムアウト（300 秒程度）に当たり、サーバーは完了してもクライアントは失敗扱いになる。ジョブの永続化はしない（転送の結果は `last_checkin_at` と `checkin` event に残る）。大きな初回投入は CLI で行う（2026-09-02） |
| 17 | 案件ごとの版マーカー `rev`（uuid4。checkin のたびに振り直す）を `case.json` に持ち、同じ名前の空ファイル `cases/<case>/.rev/<rev>` を案件フォルダに 1 個だけ置く。ワークスペース単位の集計ファイルは置かない。`open_case` は `rclone lsf` 1 回で名前を比べ、同じなら取り寄せを省略し、違う・無い・2 個以上（不定）なら取り寄せジョブを起動して最大 20 秒待つ。Drive が読めなければ取り寄せずローカル写し。全案件の版は `rclone lsf -R --include '/cases/*/.rev/*'` 1 回で読み、`kairn checkout <ws>` / UI の更新確認 / `daily` は違う案件だけ取り寄せる。既存データは `kairn drive-markers <ws>` で移行する | 差分なしの取り寄せでも 30 秒かかる。集計ファイルの read-modify-write は並列 checkin で競合し、復旧は全案件走査になる。案件フォルダ内のマーカーは案件の転送（rclone sync）と一緒に運ばれ、他の案件と干渉しない。一覧が答えるのは版だけで、内容は `case.json` にある（2026-09-02） |
| 18 | rclone の追加引数は `rules.rclone_flags`（既定は空）に持ち、rclone を呼ぶすべての箇所で共通引数の後ろに付ける。値は `--` で始まるオプションとその値だけ受け付ける。自前の OAuth client_id は kairn が設定せず、`setup` / `status` が共有 client_id を警告して README の手順を案内する（秘密の値は読まない） | Google Drive はファイルごとに API 呼び出しが要り、rclone 共有の client_id では API レートが絞られる（小ファイル多数で数分）。並列度（`--transfers` / `--drive-pacer-*`）は自前の client_id が前提なので既定では上げない。OAuth クライアントの作成はコンソールのみで自動化できない（2026-09-02） |
| 19 | 案件のステータス変更（閉じる・保留する・再開する）は人の判断。人は UI / CLI（`kairn close | suspend | reopen`）で直接変え、AI は MCP `set_case_status` で人の発言（`instruction`、必須）を添えてのみ代行する。AI の判断では呼ばず、open タスクが残っていても拒否せず件数で知らせる | 案件を閉じてよいか（残タスクの扱いを含む）は AI が決めることではない。人の発言をそのまま event の note に残すことで「誰の判断で閉じたか」を後から追える |
| 20 | 案件フォルダ内の作業領域（直下に `.git` ファイル＝git worktree、または `.kairn-nosync` があるディレクトリ）は配下ごと同期・退避・索引の対象外。通常の clone は `rules.exclude` の既定 `.git/**` で `.git/` だけを除く。判定はローカル側の転送ルートの走査で行い、rclone には `--filter '- /<dir>/**'` で渡す（`--exclude-if-present` は使わない）。既存の設定ファイルには自動で足さない | リポジトリの写しは知見ではなく、同期を遅くし検索に混ざる。目印がファイルなら判定は `is_file` 1 回で済み、worktree は何も置かずに対象外になる。rclone 1.70 の `--exclude-if-present` は同名のディレクトリがツリー内にあると転送全体が失敗する。設定ファイルを kairn が勝手に書き換えない（2026-09-02） |
| 21 | 常駐（`kairn serve`）の設定は起動時に固定せず、MCP のツール呼び出しと UI のリクエストのたびに `~/.config/kairn/config.yaml` の更新（mtime / size / inode）を確認して読み直す（`ConfigHolder`）。1 回の呼び出しの間は同じ設定を使い、ジョブは投入時点の設定を使う。読み直せない設定は無視して直前の設定で動き、警告を 1 行出す。再起動が要るのは kairn 自体の更新と unit（バインド先・ポート）の変更だけ | 運用中にワークスペースや規則を変える操作（`ws create` / `attach` / `rules …` / UI の設定）は日常的で、常駐の再起動を前提にできない。壊れた設定で常駐を落とさない |
| 22 | ワークスペースをまたぐ参照（他 ws の案件を検索する・開く）は記録される正規の経路とする。`find_cases` / `search` は `scope=auto`（自 ws に無ければ他 ws）を既定にし、呼び出し元の案件文脈 `from_case="<ws>/<case>"` があれば対象 ws の `index/access.log`（`cross_from=`）と参照元の案件の `xref` event に残す。`related` は `<ws>/<case>` を許す。判断は参照時ではなく**成果物に書く時**に行う: 他 ws から得た内容は相手の案件 ID・顧客固有の情報を書かず一般化し、出典は `related` に残す（SKILL.md）。出典の追記は MCP `link_case`（追記のみ・実在を検証・他 ws なら `xref` も記録）で AI が行い、`related` からの削除は人（UI）だけができる | 参照は止められない（エージェントはファイルを直接読める）。見えない経路より記録される経路がよい。保存先・索引・抽出の境界（1）は変えず、参照だけを開く |
| 23 | 案件の新規作成は AI も MCP `create_case` で行える（人は CLI `kairn new`）。`opened` event の `actor` は経路で分け、AI が作った案件は `actor: ai` + `agent` として残す。ステータス変更（19）と違い人の発言（`instruction`）は要求しない。作る前に Drive の `cases/<case>/` を `rclone lsf` で 1 回見て、`case.json` のある案件（別環境で作られた同じ ID）も `case.json` の無いディレクトリ（案件化前のデータ）も見つけたら作らない。Drive が読めなければ作り、衝突を確認できていないことを返り値に書く | 実際にはエージェントが CLI を自力で叩いて案件を作っており、その記録が `actor: human` として残っていた（`kairn new` は human 固定）。MCP に正規の経路を置く方が「誰が作ったか」を正直に残せる。`instruction` を必須にしても AI が発言を捏造できる以上は強制力にならず、作業の途中で案件が要ると分かる場面を塞ぐだけ。一方 Drive との衝突は `checkin`（案件単位の rclone sync）が Drive 側を `_deleted/` へ退避するため実害があり、10 秒の照会 1 回で防げる（2026-09-04） |
